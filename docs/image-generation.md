# Native image generation

Optional image models generate or edit images through the same core auxiliary-task meter as
classifiers. The initial adapter implements the pinned Pi OpenRouter image-modality protocol:
POST to the configured chat/completions endpoint, stream false, explicit image/text modalities,
and native message.images data URIs in the response. It is a distinct model task, not a chat
agent asked to describe an image. SDK and Code Mode share owned preparation, approval, token
reservations, cancellation and Started/Finished usage records.

## Configuration and API

Enable the runtime auxiliary-models feature, or the frontend's existing optional code-mode
feature. Neither is enabled by default. A trusted user profile declares image_models and its
credential reference; code_mode.model_profiles selects trusted names. Project settings can
select profiles but cannot define routes or private storage. Example trusted settings:

```json
{
  "version": 1,
  "profiles": {
    "painter": {
      "provider_id": "openrouter",
      "base_url": "https://openrouter.ai/api/v1",
      "api_key_env": "OPENROUTER_API_KEY",
      "image_models": [{
        "provider": "openrouter", "id": "YOUR_IMAGE_MODEL",
        "name": "Painter", "images": true, "text_output": true,
        "context_tokens": 65536, "output_reservation": 8192
      }]
    }
  },
  "settings": {
    "code_mode": {
      "enabled": true, "only": true, "model_profiles": ["painter"]
    },
    "execution": {"max_auxiliary_calls": 8}
  }
}
```

Replace the model ID with one served by the selected endpoint and declare its actual input,
text-output and token capabilities. No live discovery/probing or image model is enabled
implicitly. Profile response/connect/time limits and proxy policy are host controlled;
profiles containing image models default to a 120-second request timeout and a 24 MiB bounded
response. A mixed profile shares transport settings, while classifiers retain their own 2 MiB
response ceiling. Parent/tool/script deadlines can be shorter. There are at most 64 native
models per profile and 128 total selected classifiers/images across at most 16 profiles.

The main agent still uses its separately selected chat route. Image routes and keys are
absent from serialized runtime snapshots. Model catalog entries expose capabilities and
configured credential availability, not live authentication or routing authority. A separate
model_generate_images Command tool is registered only when image models are selected; its
owned prepared plan includes captured inputs and a bounded preview without image base64.
Missing output storage rejects before inference. Extension name collisions fail closed.

```js
const painters = await models.getAvailableOfType("image");
const result = await models.generateImages(painters[0], {
  input: [{type: "text", text: "A fox in the snow, watercolor"}]
});
if (result.stopReason !== "stop") text(result.errorMessage);
else {
  for (const block of result.output) {
    if (block.type === "image") await image(block);
    else text(block.text);
  }
}
```

getModelsOfType/getAvailableOfType/getModelOfType share the host catalog. generateImages uses
only provider/id from its model argument. It accepts Pi-style text blocks and bounded inline
image blocks with data/mimeType; generated image blocks with artifact references can also be
passed back as reference/edit input when the optional images decoder is enabled. SDK callers
use ImageGenerationContext with typed Text or Image { source: ImageSource } blocks. URL sources
are rejected; no input or response URL is fetched. Artifact inputs resolve against current
scoped storage, capture a bounded normalized snapshot before approval and cannot install IO
rights. Codec-free hosts can use inline inputs and capture raw generated bytes.

## Output and storage

Successful results contain provider/model, stopReason stop, optional reported usage and an
output array of text or `{type: "image", artifact: ArtifactRef}` blocks. The intentional host
representation differs from Pi's in-memory base64 image block: raw generated bytes are stored
in explicit scoped artifacts, while image(block) and reference editing keep the same workflow.
This bounds VM replies and canonical records. The core/provider SDK result retains typed
GeneratedBlock raw bytes for hosts owning their own delivery policy. Stock --no-session hosts
have no implicit output storage and reject generation before HTTP.

All output envelopes are validated before delivery. There must be at least one image and at
most four, with at most 8 MiB each / 16 MiB aggregate; text is at most 64 KiB and must be declared
by text_output. Responses are capped at 24 MiB including JSON/base64 and by the host's smaller
configured ceiling. Empty/text-only, malformed base64, remote URLs, excessive output or
non-stop completion fail explicitly. MIME routing accepts PNG/JPEG/GIF/WebP; raw capture does
not guarantee a valid codec. Optional model-preview resolution separately validates actual
codec/dimensions and reports omission. Capture completeness and preview usability are distinct.

Delivery admits complete result metadata and stages the entire image set before publication.
A failed stage releases pending writers without publishing the preceding staged images.
Publication failures report delivery_complete false and any captured_artifacts receipts;
individual immutable raw captures may exist without a complete result. Cancellation/process
loss during publication can leave scoped captures without delivered receipts, subject to host
retention limits. Neither situation repeats completed inference. Storage delivery is bounded
by the remaining tool timeout and a five-second ceiling. Text/results must fit the complete
current tool-output budget; they are not silently clipped into a valid-looking answer.

Canonical generated results retain references, never raw response base64. Real caller-supplied
inline inputs and scripts remain canonical facts and are not rewritten. Ordinary direct tools
project image artifacts using the existing scoped preview mechanism. Code Mode leaf results
retain raw references, but only explicit await image(block) selects pixels for the next outer
model request. Filtering generated output does not refund execution, storage or usage.

## Shared native transport

The image client and Runtime-created image routes support [shared native transport bindings](auxiliary-transport.md).
Approved input/modalities and private credentials remain protected; allowed tracing/service
controls and safe response observers use the common driver. No retries or new grants are added.

## Metering and failure

Image and classifier tasks share four per-run slots, the hard 128-task ceiling, configured
max_auxiliary_calls and the parent token/tool/time/output budgets. Input is at most 32 blocks,
64 KiB total text and four image snapshots. Estimated auxiliary_images_v1 counting excludes
base64-as-text and marks image/framing fallback explicitly; output_reservation is a conservative
token allowance, not an image byte bound or guaranteed monetary cap. Known model windows are
checked before HTTP. Parent reservations are atomic across concurrent native task types.

Started is durable before HTTP. Provider token usage is reported before image validation, so
invalid output and later archive failure still settle known service counts. Cancelled/missing
usage charges its reserved estimate with explicit uncertainty. Primary usage remains separate
from per-model auxiliary subtotals, terminal/session/RPC usage includes both, and unknown prices
stay unknown. The primary model's rate never prices all image tasks. No implicit HTTP retries
or redirects occur. Unsupported journals fail before external execution; records never restore
routing or approval authority. All these rules also apply outside Code Mode.

Ordinary provider/delivery failures return stopReason error to JS, retaining reported usage;
parent budget/cancellation still stops the run. Run outcome and durable task records distinguish
completed inference from incomplete delivery. Custom SDK hosts implement ImageGenerationProvider
and immutable ImageGenerationOperation without HTTP or frontend dependencies in core.
